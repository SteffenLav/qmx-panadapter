# Live reference windows, 2026-08-24 — 20 m, OZ1LAV JO65

Three consecutive dumped windows from the on-device WSPR receiver (dial
14.095600 MHz, QMX, dev Tab5), written by `wspr_rx.c`'s capture dump. Each
`.txt` is the output of **WSJT-X's own `wsprd`** on the same file:

    wsprd -f 14.0956 260824_1906.wav

## Why these exist

`150426_0918.wav` was the only WSPR reference in this tree, and we already
decode it, so it could not measure anything. These three are live, busy windows
with a known-correct answer from the reference decoder — so any change to our
decoder can be scored against them instead of argued about.

## The scoreboard that motivated the next piece of work

| window | `wsprd` | ours | ratio |
|---|---|---|---|
| 19:06 | 11 | 5 | 2.2x |
| 19:10 | 14 | 4 | 3.5x |
| 19:14 | 7  | 1 | 7.0x |
| total | **32** | **10** | **3.2x** |

⛔ **The gap is NOT mainly the weak-signal floor — it is `WSPR_MAX_CANDS`,
which is 8.** Every one of 127 cycles ever run reported exactly 8 candidates,
i.e. the cap was saturated 100 % of the time. At 19:10 we decoded PD2LEO -11,
G8ORM -13, G8MCD -13 and OE5MMP -18 while MISSING DD3MS -13 and PE1JXI -15,
both stronger than one we got. A sensitivity floor cannot do that. The comb
score that ranks candidates is correlation energy, not SNR, so a strong station
can rank below eight noisier peaks and never be tried.

Decode costs ~7.9 s per candidate and a cycle is 120 s, so the cap and the
every-other-cycle limit are the SAME budget: with a second capture buffer the
decode gets a full 120 s while the next capture fills, affording ~15
candidates — about what wsprd found here. Raise the cap and ping-pong together.

## These windows also FALSIFY the SLOW false-decode guard, externally

`WSPR_GUARD_SLOW_CYCLES` is 250 and is deliberately measured-only. These files
are why it must stay that way — **real stations, confirmed by wsprd, that
needed far more than 250 Fano cycles:**

| station | our cycles | in wsprd's list? |
|---|---|---|
| PA3BCA JO21 (19:06) | **336** | yes |
| G8MCD IO91 (19:06)  | **428** | yes |
| PD2LEO JO21 (19:10) | 246 — four below the threshold | yes |

Against that, the one known fabricated decode (`PH1SHX HC05 47 dBm`, from
simulation) needed 1889. The ranges overlap and there is no threshold that
separates them. Before these files the only real high-cycle decode was PA0RDT
at 1345 with no independent confirmation; now the falsification rests on
somebody else's decoder agreeing the stations were on the air.

## Provenance

Written by the device, header byte-identical to `150426_0918.wav`'s (checked by
`test/wspr_wav_harness.c`). 2,880,044 bytes each: 44-byte canonical PCM header
plus 120.000 s of 12 kHz mono 16-bit. Peak input levels 90.3 / 83.5 / 107.5,
i.e. a strong, busy band — not a marginal night.
