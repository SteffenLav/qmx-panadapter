  Troubleshooting
    • Spectrum flat / no signal → cable, power cycle, QMX firmware
    • QMX loses CAT connection → firmware version, cable, restart
    • WiFi won't connect → SSID/password, 2.4 GHz preferred, client isolation
    • FT8 slow/stopped → WiFi interference, USB issue, restart
    • FT8 transmit doesn't key → firmware version, CAT dead, sim mode check
    • Battery drains fast → brightness, WiFi, FT8 CPU, battery age
    • Time wrong, FT8 fails → WiFi SNTP, manual time set, RTC setup
    • Web UI won't load → WiFi off, wrong IP, client isolation, server crash
    • Settings disappear → NVS reset, backup/restore via config
    • Collecting diagnostics (web UI, serial console, capture_serial_log.ps1)
    • When stuck → GitHub issues with logs, hardware details, firmware versions

🔧 DEPLOYMENT OPTIONS
════════════════════════════════════════════════════════════════════════════════

Option 1: Manual SCP (Simplest for First Deploy)
  mkdocs build
  scp -r site/* user@server:/var/www/qmxpanadapter.lav.dk/

Option 2: GitHub Actions (Fully Automatic)
  1. Add secrets: DEPLOY_HOST, DEPLOY_USER, DEPLOY_KEY, DEPLOY_PATH
  2. Push to main → GitHub Actions builds & deploys
  3. Zero manual steps after setup

Option 3: mike Versioning (Multiple Versions)
  mike deploy 0.18.8 latest
  → Readers can switch versions via dropdown

See DEPLOY_DOCS.md for:
  • SSH key setup (one-time)
  • GitHub Actions configuration
  • Web server setup (Nginx/Apache examples)
