# v0.9.9.1 - Trivial-debt cleanup pass

Maintenance release. Five small cleanups identified during the v0.9.9 backlog review. No new features, no behaviour changes for normal operation - one user-visible fix (dBm axis labels now correctly hidden in flat mode), one developer-quality-of-life fix (firmware version no longer drifts in the boot log), and three doc/source hygiene fixes.

## Changes

### Dynamic firmware version in boot log
`bsp_info.c` previously had `FW_VERSION` hardcoded as a string literal. Across several releases this drifted - v0.9.8 still printed `firmware: v0.9.7` at boot. Now uses `esp_app_get_description()->version`, which the build system populates automatically from `git describe`. The boot log will always match the actual git tag from now on, with no manual maintenance step.

Required adding `esp_app_format` to `PRIV_REQUIRES` in `main/CMakeLists.txt`.

### Hide dBm axis labels in flat mode
In flat-spectrum mode the spectrum axis represents dB-above-noise-floor, not absolute dBm. The `-30 dBm` / `-130 dBm` corner labels were left visible since v0.9.2 and were misleading in that mode. Now hidden via `LV_OBJ_FLAG_HIDDEN` toggled in both `ui_set_flat_mode()` and the drawer flat-switch callback.

### README: Network CAT bridge moved from "Longer term"
The rigctld TCP server (port 4532) shipped in v0.9.6 but the "Longer term" roadmap section still listed it as a planned item. Removed the bullet, and corrected one prose mention in the WiFi/SNTP section that referred to it as upcoming.

### Mojibake cleanup
14 instances of em-dash UTF-8/Latin-1 round-trip corruption removed from `main.c` (3 instances, single-encoded) and `main/ui/wifi_config.c` (11 instances, double-encoded). Replaced with ASCII `-` per the README mojibake lesson - safe against any future re-encoding round-trip.

## Backlog items closed without code changes

Three items in the trivial-debt list were stale and no longer applicable:

- `ui_set_db_labels_internal` warning - the symbol no longer exists in the source.
- `m5stack_tab5.c` unused-variable warnings (`gain`, `gpio_if`) - already had `(void)var;` suppressors in place.
- Consolidate dB-range defines - on review the apparent duplication is intentional separation of concerns (runtime user preferences vs NVS defaults vs WS wire-protocol range vs waterfall clamp limits). Closing as not-a-real-issue.
