# v0.10.0-beta3 -- Onboard FT8 with stable modals + 20-row decode display

Hotfix release on top of beta2, restoring full 20-row FT8 decode visibility
while eliminating the WiFi-modal-during-FT8 crash that motivated beta2's
band-aid row count reduction.

## What changed

### LVGL static memory pool moved to PSRAM (the real fix)

The root cause of the beta1/beta2 crashes was finally identified:
LVGL's builtin allocator uses a `static` array in `.bss` (sized by
`CONFIG_LV_MEM_SIZE_KILOBYTES`, default 64 KB) for *all* widget
allocations. Every `lv_obj_create`, `lv_label_create`, modal build,
drawer build, and row pool allocation comes from this pool -- which is
**not measured by `heap_caps_get_free_size(MALLOC_CAP_INTERNAL)`**.
That's why all earlier heap instrumentation showed `delta=0 B` per
allocation: we were measuring the wrong pool.

At 64 KB, the pool could not fit:

- Main UI widgets (~10 KB)
- WiFi modal (~25 KB -- includes the on-screen keyboard)
- Identity modal (~25 KB)
- Settings drawer (~10 KB)
- 20-row FT8 pool (~40 KB)

Cumulatively that's ~110 KB -- well over the 64 KB ceiling. Hitting it
manifested variously as NULL store fault, `lv_obj_create` silent hang,
or `lv_obj_allocate_spec_attr` lockup, depending on which allocation
sequence overflowed first.

**Fix**: pool size doubled to 128 KB and relocated from internal SRAM
(default `.bss`) to PSRAM (`.ext_ram.bss`):
CONFIG_SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY=y
CONFIG_LV_MEM_SIZE_KILOBYTES=128
The `LV_ATTRIBUTE_LARGE_RAM_ARRAY` macro is **not** exposed as a
Kconfig symbol in the ESP-IDF LVGL component, so it must be injected
as a global compile define via `idf_build_set_property()` (NOT
`add_compile_definitions()` -- the latter does not propagate into
managed components):

    idf_build_set_property(COMPILE_DEFINITIONS
        "-DLV_ATTRIBUTE_LARGE_RAM_ARRAY=EXT_RAM_BSS_ATTR" APPEND)

This call must appear **before** `project()` because component
registration captures `COMPILE_DEFINITIONS` at that point.

Net memory effect: internal heap at boot increased from ~197 KB
(beta2) to ~262 KB (+64 KB, because the static array's .bss footprint
moved out of internal SRAM entirely), while PSRAM dropped by exactly
128 KB. DMA-capable allocations (SDIO RX for WiFi, USB host pipes) now
have plenty of headroom.

### MAX_ROWS restored to 20

beta2's `MAX_ROWS=12` workaround is reverted. Full 20-row FT8 decode
display is back. On a busy band slot we now routinely see 18-25
distinct callsigns, which the 12-row pool would have truncated.

### Modals and drawer pre-built at boot

`wifi_config_modal_init()`, `identity_config_modal_init()`, and
`drawer_build()` are now called from `ui_init()` at boot, when the
LVGL pool is empty. This:

- Eliminates first-tap stutter for the burger menu
- Eliminates the WiFi-modal-during-FT8 crash from beta1 (modal
  builds at boot when memory is uncontested, not at runtime when the
  FT8 row pool has consumed half the LVGL pool)
- Makes drawer and modal opens effectively instant

### Stability validation

Tested live on 20m FT8 (14.074 MHz) for ~25 consecutive 15-second
slots without WiFi/CAT/audio disconnects, with the following exercised
during the run:

- Mode toggle Panadapter <-> FT8 (twice)
- Settings drawer open/close during FT8 mode
- WiFi config modal open/close during FT8 mode

Internal heap remained stable at 101-104 KB across all slots (no leak).

## Known limitations carried over from beta2

- ENUM `CHECK_SHORT_DEV_DESC FAILED` warning at boot is pre-existing
  USB-host enumeration retry behaviour, harmless.
- The brief `RX ... DROPPED=N (ring full)` line during initial QMX
  descriptor enumeration is pre-existing (audio ring fills during the
  ~400 ms descriptor dump pause).

## Files changed

- `CMakeLists.txt` -- new `idf_build_set_property()` call before
  `project()`
- `sdkconfig` / `sdkconfig.defaults` -- two new config symbols
  (`LV_MEM_SIZE_KILOBYTES=128`, `SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY=y`)
- `main/ui/ft8_screen_view.c` -- `MAX_ROWS` 12 -> 20, comment block
  updated to document the pool architecture
- `main/ui/ui.c` -- `ui_init()` now calls modal + drawer init at boot
- `main/ui/wifi_config.{c,h}` -- new `wifi_config_modal_init()`
- `main/ui/identity_config.{c,h}` -- new `identity_config_modal_init()`
