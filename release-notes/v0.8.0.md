## Highlights  WiFi station mode with on-screen credential entry. The Tab5 now connects to the local network via its on-board ESP32-C6 co-processor (`esp_hosted` over SDIO) and syncs UTC time via SNTP on connect. No rebuild required to change networks - credentials are entered through a full-screen LVGL modal launched from the settings drawer and persisted to NVS.  ## What's new  ### WiFi credential modal - Full-screen overlay launched from a new **WiFi** button in the settings drawer - SSID textarea pre-fills from NVS on each open; password textarea always starts blank (masked) - On-screen keyboard appears when a field is focused, hides on Enter or its close icon - **Save** writes credentials to NVS and triggers an immediate disconnect / reconnect - **Cancel** discards changes - 32-char SSID / 64-char WPA2 password limits  ### SNTP time sync - UTC sync on every successful WiFi connect (`pool.ntp.org`) - Unblocks the planned onboard FT8 decoder, which requires accurate time  ### Why this matters STA mode is now in place. The longer-term web UI and network CAT bridge items just need their application-layer code on top.  ## Under the hood  Two stacked bugs hunted down and fixed during bring-up:  - **Symbol collision** - local `wifi_start(void)` collided with esp_hosted''s `wifi_start(req)`; the link picked the wrong one with `--whole-archive`. Renamed local symbols to `panadapter_wifi_*` prefix. - **Auto-init didn''t fire** - `esp_hosted_host_init.c`''s `__attribute__((constructor))` was not auto-running. Worked around with an explicit `esp_hosted_init()` call at the start of `wifi_task`.  ## Known issues  - WiFi credentials are stored in the default `nvs` partition and may be wiped by merged-binary reflashes (fixed in v0.9.4)  ## Flashing  Merged binary `qmx_panadapter-v0.8.0-merged.bin` attached below.
