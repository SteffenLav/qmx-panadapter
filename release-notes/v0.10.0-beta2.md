# v0.10.0-beta2 - WiFi modal hotfix

Hotfix for v0.10.0-beta1.

## The bug

In v0.10.0-beta1, opening the **WiFi** button from the settings drawer caused the device to flash teal briefly and then reboot. The Tab5 was unable to enter WiFi configuration, which blocked SNTP / FT8 / web UI for any user who hadn't already configured WiFi in an earlier firmware.

First reported by Ken (KF0AYY) on a fresh Tab5 received today, reproduced locally on the same firmware.

## Root cause

The FT8 view's pre-allocated row pool (20 LVGL row containers, ~150 child objects total) is created at boot and stays in the LVGL tree even when the panadapter is in normal Panadapter mode. The pool consumed enough internal heap that subsequent allocations during `modal_build()` for the WiFi modal hit fragmentation: `lv_draw_label` was called with a NULL memcpy destination (a downstream allocation had returned NULL silently) and faulted on the first render of the modal.

Stack trace: `lv_memcpy` -> `lv_draw_label` -> `draw_main` (lv_label.c:838) -> render task.

## The fix

Reduced `MAX_ROWS` from 20 to 12 in `main/ui/ft8_screen_view.c`. This drops boot-time LVGL heap pressure below the threshold that breaks the modal. WiFi modal now opens cleanly.

12 rows is enough to show all decoded callsigns from a typical FT8 slot (busy 20 m slots produce 25-50 decodes, but only the most recent 12 are kept in the visible list -- older entries are still tracked in the underlying data layer, just not displayed).

## TODO for v0.10.0-beta3 (or later)

This is a band-aid, not a proper architectural fix. The right answer is to defer the row pool's creation until the user actually enters FT8 mode, then build all 20 rows. When they leave FT8 mode, the pool can be torn down. That removes the boot-time LVGL pressure entirely and lets the WiFi modal (and any future modal) breathe.

## Other notes

The screenshot-procedure fix landed between v0.10.0-beta1 and now (commit `e77bb94`): partial-frame captures during FT8 view rendering are now stable. Already in `main` since this morning.
