## Highlights

The Tab5 is now a Hamlib network rig adapter. WSJT-X, fldigi, N1MM and any other Hamlib-aware app on the LAN can talk to the QMX through the Tab5 -- frequency tracking, mode and passband control, S-meter reads. The QMX itself sees only its existing USB CAT link from the Tab5; everything else is on the network.

## What's new

### Hamlib rigctld TCP server on port 4532

The Tab5 listens on port 4532, the standard rigctld port. Configure any Hamlib-aware app to use rig model "NET rigctl" (model 2) and point it at `<tab5-ip>:4532`. No serial port plumbing, no virtual COM trickery, no extra USB cables.

Supported commands (Hamlib protocol):

- `f` / `F nnnn` -- get / set frequency
- `m` / `M MODE PASSBAND` -- get / set mode + passband (USB, LSB, CW, AM, FM, PKTUSB, PKTLSB, RTTY, FT8, CWR all map to Kenwood mode digits)
- `v` -- get VFO (always VFOA -- QMX has one VFO)
- `s` -- get split (always 0 -- no split via CAT)
- `t` -- get PTT (always 0 -- we do not TX-control)
- `\dump_state`, `\chk_vfo`, `\get_powerstat`, `\get_lock_mode`, `\get_vfo`, `q` -- Hamlib housekeeping

Concurrent clients: up to 4 simultaneous Hamlib connections, each in its own task with an 8 KB stack. CAT writes to the QMX are naturally serialised through the existing 200 ms rate-limit, so concurrent clients do not stomp on each other.

### Underlying CAT setters

Two new setters on top of the existing `cat_set_frequency`:

- `cat_set_mode(const char *)` -- translates Hamlib mode strings to Kenwood digits and sends `MDn;`
- `cat_set_passband_hz(uint32_t)` -- sends `FWnnnn;`

Both share the same 200 ms TX rate-limit and refuse cleanly with `ESP_ERR_TIMEOUT` if the bus is busy.

## How to test

From any Windows / Linux / Mac box with Hamlib installed:

    rigctl -m 2 -r 192.168.1.213:4532

At the Rig command prompt, try:

    f                           -> reads frequency
    M PKTUSB 3200               -> sets mode and passband
    F 14070000                  -> sets frequency to 14.070 MHz

For WSJT-X: Settings -> Radio -> Rig "Hamlib NET rigctl", Network Server `192.168.1.213:4532`. Test CAT -- the radio name should turn green.

## Known issues

- Tab5 device top-bar "Center Freq" label can be sticky: it updates only on some CAT poll cycles, so a network-set frequency may appear in the spectrum and waterfall instantly while the on-device top bar lags by a few seconds. Underlying CAT state is correct -- the browser top bar and the `/api/status` JSON show the new value immediately. Tab5 label redraw timing will be revisited in a follow-up release.
- Hamlib commands not in the supported list above return `RPRT -8` (proto error) for single-letter commands or `RPRT -11` (not implemented) for backslash extended commands. WSJT-X and fldigi only need the supported set; if your app needs something else, open an issue.
- Set-mode commits the mode but the optional passband part is best-effort: if the 200 ms TX rate-limit is hit between mode and passband, the passband write silently drops. Cosmetic for WSJT-X / fldigi which do not currently set passband.
