## Highlights

DSP cleanup release. Removes an O(N^2) insertion-sort median that was running on every FFT frame -- legacy from Phase 5.8 calibration work, where the calibration value has long since been locked in. Also demotes two per-second debug log lines to ESP_LOGD.

No new features. This is a maintenance release between v0.9.6 and the next feature batch.

## What's changed

### Removed: per-frame O(N^2) median sort in dsp.c

The Phase 5.8 calibration block ran an insertion sort over 1024 floats every FFT frame -- somewhere between 15 and 30 ms of dead CPU per frame, all to compute a median that was logged once per second. The calibration value `DSP_DB_CALIBRATION_OFFSET = -148.0` is hard-coded and locked, so the runtime computation served no purpose. Removed entirely. Also recovers a 4 KB static buffer (`s_med_buf[DSP_FFT_SIZE]`).

### Demoted: per-second log lines

- `dsp: Spectrum: min=... max=... mean=...` -> ESP_LOGD (was ESP_LOGI)
- `audio: RX nnnn pairs/s peak L=... R=...` -> ESP_LOGD (was ESP_LOGI)

Both were dev-time diagnostics that lived past their usefulness. Monitor output is now noticeably quieter; ESP_LOGW drop-warning paths in audio.c are unchanged so real problems still surface.

## Honest caveats

The waterfall-scroll jumpiness reported during v0.9.6 testing is **not fixed in this release**. The DSP cleanup was an attempt at it; the symptom persists. Root cause remains under investigation -- best evidence so far: stops when QMX is disconnected, ~1/sec irregular cadence, predates v0.9.5/6. The two reductions in this release are real CPU savings regardless of whether they relate to that symptom.
