## Highlights  Phase 2 web UI: HTTP status server and binary WebSocket spectrum streaming on the LAN. This release ships the *server* side; v0.9.0 added the polished browser front-end.  ## What's new  ### HTTP status server (Phase 1) - `GET /` - landing page placeholder - `GET /api/status` - JSON: battery level / charging, WiFi SSID / RSSI / IP, current VFO frequency  ### WebSocket spectrum streaming (Phase 2) - `GET /ws` - binary WebSocket; each 1026-byte frame is `[type=0x01][reserved=0][1024 x u8 quantised -130..-30 dBm]` at ~10 fps - Single client per session; QMX dial frequency lands at the visual centre (12 kHz IF offset is server-side)  ### Local IP in the bottom bar The Tab5''s IP address now appears in the bottom status bar after SSID and RSSI - so you can find it without checking the boot log.  ## Under the hood  - `CONFIG_HTTPD_WS_SUPPORT=y` enabled - ESP32-P4 PIE / vector FFT (`dsps_fft2r_fc32_arp4.S`) crashed deterministically under sustained WS load (Load fault, `MTVAL=0x9fec8998`); fell back to `CONFIG_DSP_ANSI=y` (portable C FFT), ~10% FPS cost - `httpd_ws_send_frame_async` with a stack-local frame struct silently dropped frames; switched to synchronous `httpd_ws_send_frame` inside the `/ws` handler loop  ## Known issues  - Settings stored in the default `nvs` partition may be wiped by merged-binary reflashes (fixed in v0.9.4)  ## Flashing  No merged binary attached to this release.
