## Highlights  Settings and WiFi credentials now survive firmware updates. The "Mode: FSK" label is now "Mode: DiGi" on the top bar.  ## What's new  ### Persistent settings across firmware updates  WiFi credentials, dB sliders, EMA alpha, IQ flag, last VFO, and flat-mode toggle are now stored in a dedicated `user_nvs` partition placed beyond the application image. Updates via web.esphome.io that use the standard (non-erase) write path preserve everything - flash the new firmware, the device comes back up with your settings intact.  **One-time upgrade pain:** the first boot after installing v0.9.4 starts with defaults (re-enter WiFi creds, re-tune sliders). From v0.9.4 onwards, future updates preserve all settings.  **Caveat:** "Erase device" / full chip wipe in your flasher will of course erase user_nvs too. That''s the expected behaviour - use the non-erase update path to preserve settings.  ### DiGi label  QMX mode 6 (used for FT8, JS8, RTTY via digi soundcard modes) now reads "Mode: DiGi" on the top bar instead of "Mode: FSK". Touch-snap step (100 Hz) and passband geometry (USB-like) unchanged.  ## Under the hood  - New partition table with `user_nvs` (data / nvs, 0x810000, 0x6000) after factory app - `storage` SPIFFS partition moved to 0x820000 (was unused, no data loss) - `settings_init` switched to `nvs_open_from_partition("user_nvs", "qmx", ...)` - Mode-name array in `cat.c` outputs `DiGi` / `DiGi-R` for Kenwood mode digits 6 / 9 - `strstr(s_current_mode, "FSK")` matches in `ui.c` switched to `"DiGi"`  ## Known issues  (Carried from earlier releases.)  - dBm axis labels (-30 / -130) still render in flat mode where the axis represents dB-above-floor; grid lines are correctly hidden but labels still show - LVGL software rotation costs ~50% FPS (sw_rotate=1, LV_DISPLAY_ROTATION_90); native portrait rendering on the roadmap  ## Flashing  Merged binary `qmx_panadapter-v0.9.4-merged.bin` attached below.
