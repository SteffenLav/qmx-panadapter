# v0.10.0-beta1 - Onboard FT8 RX

First **public beta** of onboard FT8 reception. The Tab5 now decodes FT8 directly on the ESP32-P4 with no PC required.

## What's new

### Onboard FT8 RX decoder

Switch to a dedicated FT8 view from the settings drawer (**Mode: FT8**). The Tab5 captures 15-second FT8 slots from the QMX I/Q stream, decodes them via vendored `ft8_lib` (kgoba), and renders a scrollable decode list.

**Columns:** CALL / MESSAGE / COUNTRY / SNR / KM / BRG / HRD.

- DXCC country resolved from a ~190-entry prefix table with longest-prefix match (handles common `/P` `/M` suffixes).
- Distance + bearing computed great-circle from the operator's grid square to each decoded station's grid (when a grid is present in the FT8 message).
- SNR is a coarse proxy from the decoder score and **not** WSJT-X-equivalent dB yet.
- New **Identity** modal in the drawer captures operator callsign + Maidenhead grid (persisted to NVS).

A busy 20 m slot typically yields 25-50 decoded callsigns.

### FT8 view stability

The first internal implementation crashed after 1-3 minutes of FT8 decoding (`lv_obj_clean` + `lv_obj_create` cycle leaving stale draw queue entries and fragmenting internal heap with ~840 local-style allocations per refresh). Rebuilt the view around:

- A pre-allocated pool of 20 LVGL row containers.
- Shared `lv_style_t` objects for the call / message / country / SNR / km / brg / heard columns (~8x reduction in local-style allocations).
- Dirty-tracked `lv_label_set_text` updates so unchanged rows don't trigger LVGL invalidation.

Soaked 22+ minutes of continuous decoding plus drawer-open / mode-toggle stress without a reboot; heap stable at 39 KB internal free across slots.

### Per-unit IF calibration trim

New slider in the settings drawer (between CW Pitch and Waterfall colour map): **+/-200 Hz in 10 Hz steps**, persisted to NVS. Compensates for per-unit QMX local oscillator variance that shifts the +12 kHz IF baseband injection by a few tens of Hz.

Reported by Ken (KF0AYY) on groups.io, whose unit needed about -55 Hz to land on centre. Default is 0; existing units are unaffected unless the slider is moved.

Internally, the bin shift math (IF_OFFSET_HZ -> bins) was centralised in `ui_get_if_bin_shift(n_bins)` so both `ui_push_spectrum` (spectrum) and `render_waterfall_tick` (waterfall) apply the same offset.

## Known limitations (beta)

- **RX only.** Transmit is the v0.11 target. The QMX side of TX is already in place via existing CAT setters (`cat_set_mode`, `cat_set_passband_hz`); only the FT8 TX sequencer + UI need to land.
- **SNR is a proxy**, not calibrated to 2500 Hz noise BW. WSJT-X-equivalent SNR is on the post-beta list.
- **No ADIF logging** yet (v0.13).
- **Mode switching discards panadapter state.** Going from Panadapter -> FT8 -> Panadapter loses the waterfall history and resets the IQ balance estimator. Accepted trade-off for the simpler RX-only release.
- **Long-session stability not yet fully soaked.** Internal soak passed at 22 minutes. Multi-hour and overnight tests will run during the beta. If you see reboots while in FT8 mode, please open an [issue](https://github.com/SteffenLav/qmx-panadapter/issues) with the boot log immediately preceding the reboot.
- **FT8 requires accurate UTC.** WiFi must be configured first so SNTP can run on connect.
