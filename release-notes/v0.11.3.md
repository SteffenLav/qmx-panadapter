## v0.11.3 — Browser parity: interactive controls, click-to-tune, zoom sync

### Browser improvements

- **Interactive top-bar dropdowns.** Band, Mode, BW, and Zoom pills are now clickable and open dropdown panels matching the Tab5 top-bar behaviour. Selecting a band, mode, BW preset, or zoom level sends the command to the QMX/Tab5 via the new `POST /api/cmd` endpoint.
- **Click and drag to tune.** Click or drag anywhere on the spectrum or waterfall to tune the QMX to that frequency. A cyan cursor line tracks the pointer with a live frequency readout above it. Mode-aware step rounding applied (CW=10 Hz, DiGi=100 Hz, SSB=500 Hz, AM/FM=1 kHz). Commits on release; no snap-to-peak (browser has no DSP access).
- **Zoom and pan synced to Tab5.** The browser spectrum and waterfall now render the same zoomed window as the Tab5 — only the bins visible on the Tab5 are shown, correctly scaled. Frequency axis labels update to match the visible span.
- **Passband marker corrected.** CW passband is now symmetric around the VFO centre (matching `compute_passband_edges_hz()` on the Tab5), not offset by the CW pitch. Passband width now uses mode defaults (USB/LSB/DiGi=2700 Hz, CW=300 Hz, AM=6 kHz, FM=10 kHz) when the QMX has not yet reported a width via CAT.
- **Waterfall cursor artifact fixed.** The tune cursor is drawn on a separate overlay canvas above the waterfall, so it no longer gets blit'd into the scroll history.

### Tab5 + Browser

- **Band memory.** Switching bands now returns to the last frequency used on that band (session memory, resets on reboot). First visit to a band still uses the QMX FT8 default. Works from both the Tab5 dropdown and the browser band selector.

### Server (`/api/status` + `/api/cmd`)

- Added fields to `/api/status`: `zoom`, `pan_bins`, `cw_pitch_hz`, `if_cal_hz`, `bands[]` array.
- New `POST /api/cmd` endpoint accepts: `set_freq`, `set_band`, `set_mode`, `set_bw`, `set_zoom`.
- `httpd` config: `max_uri_handlers=8`, `lru_purge_enable=true` to prevent socket exhaustion under heavy browser use.
