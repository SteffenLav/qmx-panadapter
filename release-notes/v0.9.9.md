# v0.9.9 - Persistence and polish pass

Quality-of-life pass focused on user-facing polish: persistent settings, smarter touch-to-tune, multiple waterfall colour schemes, and a cleaner status bar.

## Highlights

### Configurable CW sidetone pitch
Touch-to-tune in CW / CW-R now applies a sidetone offset to the dial so the touched audio peak lands at the chosen pitch (default 700 Hz) rather than zero-beat. Range 400-1000 Hz in 50 Hz steps, set via a slider in the settings drawer, persisted to NVS. CW-R applies the offset with the opposite sign so the lower-sideband case is handled correctly.

### Waterfall colour maps
Four colour maps shipped: Thermal (original), Viridis, Turbo, and Grayscale. Switch instantly via a dropdown in the settings drawer; selection persists across reboots. Implementation is a single 256-entry RGB565 LUT rebuilt from per-map anchor points, so adding more maps later is one struct entry plus the anchor table.

### Snap-to-strongest-bin
The touch handler now searches +/-700 Hz around the touched position for the strongest spectrum bin and snaps to it before applying the existing mode-aware snap (CW=10 Hz, SSB=500 Hz, etc). The snap only fires when the peak exceeds the local-window mean by more than 3 dB, so touches on empty noise floor still tune precisely to the touched position.

### Bottom-bar polish
The status bar was previously a single concatenated string with cramped spacing. v0.9.9 introduces a 3-zone layout: battery icon + percentage on the left, UTC clock (HH:MM:SS) in the center, WiFi symbol + SSID + RSSI + IP on the right. Bar height bumped from 30 to 36 pixels for comfortable rendering. The status task now uses `display_lock()` for each label write (the previous single-label version did too; the regression was caught early during the rewrite).

### Last-VFO restore at boot
On startup the Tab5 displays the most recent QMX frequency immediately (from NVS), eliminating the placeholder shown during the 1-2 second wait for the first CAT FA reply. The QMX remains source of truth - the displayed VFO updates on first CAT poll if the radio's actual frequency differs.

### Settings drawer scrolling
The drawer is now vertically scrollable to fit the new CW Pitch and Colour Map controls without crowding existing widgets.

## Diagnostics

No deep architectural shifts in this release. The most interesting debugging moment was the bottom-bar status task initially calling `lv_label_set_text` from a non-LVGL task without acquiring `display_lock()` - producing frozen labels and ~1s touch latency. The fix is straightforward (wrap each setter in lock/unlock) and the lesson is documented for future label setters: any label setter called from outside the LVGL task must acquire the lock.

Also noted during the colour-map UI work: `lv_label_set_recolor()` was dropped in LVGL 9. Inline `#RRGGBB text#` syntax is gone. The U+25CF filled-circle glyph used as a coloured dot prefix isn't present in this Montserrat build (renders as tofu). Both fallbacks are simple - prefer `LV_SYMBOL_*` glyphs and per-label style colours over inline recolor.

## Carryover from v0.9.8

The 10 Hz render-rate workaround for the LVGL flush cascade remains in place. No regression observed in v0.9.9.

## Backlog status

Memory channels - long-requested - was scoped and a v2 specification drafted, but the feature is large enough to merit a focused session of its own. Pushed to a future release.

The v0.10.0 candidate (network audio bridge: Tab5 -> PC UDP audio, combined with the v0.9.6 rigctld to enable WSJT-X / fldigi on a PC while the QMX stays in the shack) remains the headline target for the next minor version bump.
