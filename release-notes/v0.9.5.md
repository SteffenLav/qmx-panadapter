## Highlights

The browser web UI is now a real operating tool, not just a "look at the spectrum" page. Full radio state parity with the Tab5, responsive single-page layout that fits any viewport without scrolling, and a complete WS architecture rework that fixed an issue where the top bar froze the moment the spectrum stream connected.

## What's new

### Browser top bar matches the Tab5

The status row above the spectrum now shows VFO, mode, band, and S-meter (S-units and dBm) updating once per second from `/api/status`. The amber centre marker on the spectrum and waterfall shows where the QMX dial is. Two grey passband edge lines on the spectrum mark the current filter window, mode-aware (USB/LSB/CW/AM/FM/DiGi all handled). A frequency axis below the spectrum shows the centre MHz plus +/-12 and +/-24 kHz tick labels.

### Responsive single-page layout

CSS Grid with `100dvh` keeps everything on one screen with no scrolling, on phone portrait through 4K landscape. Spectrum-to-waterfall ratio 1:3. Narrow-screen breakpoint shrinks fonts and hides redundant pill labels. ResizeObserver matches canvas pixel count to the layout so rendering stays sharp at any size. Tap-target flat-mode button in the top-right (the `f` keypress still works for desktop).

### `/ws` refactor: dedicated push task

The single biggest fix in this release. The previous `/ws` URI handler held the httpd worker in an infinite send loop for the whole WS session. ESP-IDF httpd serialises URI handlers per worker, so any `/api/status` request that arrived while the WS was active queued indefinitely. Browser top bar froze the moment the WebSocket connected.

New architecture: the URI handler captures `(server, fd)` on handshake and returns immediately, freeing the worker for `/api/status`. A dedicated `ws_push_task` runs the 10 fps send loop using `httpd_ws_send_frame_async` with static (not stack-local) frame buffers. On send failure the task clears the session and goes idle until the next handshake.

## Under the hood

- New getters in `ui.h`: `ui_get_mode_str()`, `ui_get_band_str()`, `ui_get_passband_width_hz()`
- New static `s_current_band[8]` cached in `ui.c`, set from each `ui_update_band()` call
- `/api/status` JSON gains: `mode`, `band`, `passband_hz`, `signal_dbm` (null until first spectrum)
- S-units derivation client-side: S9 = -73 dBm, 6 dB per S-unit, clamps S1..S9 with `S9+XX` for stronger signals
- Mode-aware passband geometry client-side: USB / DiGi / FT* / RTTY use VFO+200 .. VFO+200+width; LSB mirrors; CW / AM / FM symmetric around VFO
- Spectrum 1024 bins span 48 kHz, so 1 bin = 46.875 Hz; axis maths consistent with `ui.c` IF_OFFSET_HZ
- Bumped FW_VERSION to v0.9.5

## Known issues

(Carried from earlier releases.)

- dBm axis labels (-30 / -130) still render in flat mode where the axis represents dB-above-floor; grid lines are correctly hidden but labels still show
- LVGL software rotation on the Tab5 costs ~50% FPS (native portrait rendering on the roadmap)
- Only one browser at a time can hold the WS connection. Additional viewers get refused at handshake; `/api/status` polling still works for them.

## Flashing

Merged binary `qmx_panadapter-v0.9.5-merged.bin` attached below. Drop into [web.esphome.io](https://web.esphome.io/) from Chrome or Edge.

Settings and WiFi credentials survive the update (v0.9.4 onwards). Open `http://<tab5-ip>/` from any browser on the same network -- the IP is shown in the bottom status bar of the Tab5 and in the boot log.
